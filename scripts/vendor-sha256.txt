# 官方 CDN 上守护进程二进制的 sha256。
#
# 为什么要钉死：同一个 URL、同一版本、同一 commit，两次取到的字节数并不相同
# （例如 3.1.9 的 natfrp-service 曾出现 20,250,784 与 20,245,538 两种大小），
# 说明上游会重新打包。这些二进制最终以 root 运行，内容必须在构建时校验。
#
# 注意：这里钉的是 CDN 原始文件（ipk 里解出来的那一份）。OpenWrt 打包时会再处理一遍
# （实测少了 5,246 字节填充，GNU BuildID 不变），所以不要拿 APK 内的文件来比这个值。
#
# 仓库内 vendor/blobs/<blob-arch>/ 存档了同一份解包二进制：CI 先尝试 CDN，
# 拉取或解包失败时自动回退到存档；存档同样按本表校验。更新版本时请同步替换存档，
# 否则 CI 会在「校验仓库存档」步骤失败。
#
# 格式：<blob-arch>/<文件名> <sha256>
# 校验不通过时 CI 直接失败；没有收录的架构会打印警告并跳过校验。
